## 1. カレンダー層（実装済み）

### 1-1. 予定の識別

- **単発予定**: `eventIdentifier` のみをキーにする。
- **繰り返し予定**: `eventIdentifier` + `occurrenceDate`（その回の元の開始時刻）。

繰り返しかどうかは EventKit 側（`hasRecurrenceRules || isDetached`）で判定する。
開始時刻をキーに含めないため、時刻を動かしても同一の予定として認識される。

### 1-2. 枠（1日あたりのサポート対象）

- 無料版は1日3件、Premium は無制限。
- **第1段階（前日まで）**: 開始時刻の昇順で上位3件。同一時刻は `eventIdentifier` の昇順。
- **第2段階（確定後）**: 空き枠がある場合のみ、`creationDate` の昇順（登録順）で追加する。
  既に確定した枠は押し出さない。
- 対象外: 終日予定、座標が恒久的に解決できなかった予定、対象日に重ならない予定。
- 日跨ぎ予定は、またぐ全ての日でそれぞれ1枠を消費する。
- 前日にアプリを開かなかった場合、当日に第1段階を実行する。このとき開始時刻が
  現在時刻より前の予定は対象から除外する。

### 1-3. 枠の解放

| 状況 | 枠 |
| --- | --- |
| 完了した（予定はカレンダーに残っている） | 保持する |
| 支援を送信する前に予定が消えた | 返す（次の予定に回る） |
| 支援を送信した後に予定が消えた | 返さない（消費済みとして数える） |

場所が無かった予定に後から場所が追加された場合は、第2段階の通常の追加として扱う。
空き枠があれば入り、無ければ入らない。1日の上限3件は常に超えない。

### 1-4. 完了判定

`now >= event.startDate` で完了とする。終了時刻ではなく開始時刻が基準。
通知の送信有無は完了の条件にしない。終日予定は開始時刻が 0:00 なので、その日になれば完了扱い。

完了後はスナップショットを凍結する。外部で編集されても値を更新せず、編集回数も増やさない。
外部で削除されてもスナップショットは保持する。UI 側での編集・削除のブロックは後続フェーズで扱う。

### 1-5. 変更検知

比較対象は `startDate` / `endDate` / `latitude` / `longitude` の4項目のみ。
タイトルやメモは保存も比較もしない。同時に複数項目が変わっても編集は1回と数える。
無料版は `editCount >= 3` で上限とするが、上限を超えても計算は最新のデータで続行する。

### 1-6. 座標の解決

開始時刻順に1件ずつ逐次で解決し、枠が埋まった時点で打ち切る（通常ちょうど3回）。
第2段階では登録順で解決する。並行実行はしない（レート制限のため）。

| 結果 | キャッシュ | 枠 |
| --- | --- | --- |
| 成功 | 保存（無期限） | 消費する |
| 一時的な失敗（通信断・レート制限） | 保存しない | 消費する |
| 恒久的な失敗（住所として解決できない） | 保存（24時間） | 消費しない |

### 1-7. 保存期間

| データ | 削除条件 |
| --- | --- |
| スナップショット | 完了から14日経過 |
| 枠の状態 | その日が3日より前 |
| ジオコーディング（成功） | 削除しない |
| ジオコーディング（失敗） | 24時間経過 |

14日なのは、週次サマリーが「先週」を表示するため。月曜に閲覧する場合に最大13日前が必要になる。

## 2. 移動時間（後続フェーズ・未実装）

以下は確定した仕様。**このリポジトリのコードには一切反映していない。**

### 2-1. 移動手段の判定

| 条件 | 移動手段 |
| --- | --- |
| 直線距離 1.5km 以下 | 徒歩 |
| 直線距離 1.5km 超 | ユーザーが選択した交通手段（電車 / 車） |

ユーザーの選択は `UserPreferences.primaryTransport`（`.transit` / `.automobile`）に持つ。

### 2-2. 出発時刻

```
出発時刻 = 開始時刻 − 移動時間 − 10分
```

バッファの10分は全ての交通手段で一律。徒歩でも電車でも車でも変えない。

### 2-3. 出発地点

| 対象 | 出発地点 |
| --- | --- |
| その日の最初のサポート対象 | 自宅 |
| 2件目以降 | 前のサポート対象の場所 |
| 前のサポート対象に場所がない | 自宅 |

自宅の座標は `UserPreferences.homeLatitude` / `homeLongitude` に持つ。

## 3. 通知（後続フェーズ・未実装）

以下は確定した仕様。**このリポジトリのコードには一切反映していない。**

### 3-1. 通知タイミング

| プラン | 通知 |
| --- | --- |
| Free | 出発時刻 / 開始時刻 の2回 |
| Premium | 開始1.5時間前 / 開始1時間前 / 開始30分前 / 出発時刻 の4回 |

### 3-2. 出発時刻が変わった場合

| 条件 | 挙動 |
| --- | --- |
| Premium で出発時刻が10分以上早まった | 即時通知 |
| 新しい出発時刻が既に過ぎている | 緊急通知 |

### 3-3. カレンダー層との接続

通知を送信したら `EventSnapshot.supportSentAt` に送信日時を記録する。
呼び口は `Repository.markSupportSent(for:at:)`。この値が枠を返すかどうかの判定に効く
（1-3 を参照）。
